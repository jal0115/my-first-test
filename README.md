\# F.CSA313 — Лаборатори №1: Playwright UI автомат тест



\## Юу хийсэн

\- Playwright төсөл (TypeScript) үүсгэж, https://www.saucedemo.com дээр 3 тест бичсэн:

&#x20; 1. Амжилттай нэвтрэх (`standard\_user` / `secret\_sauce`)

&#x20; 2. Амжилтгүй нэвтрэх — буруу нууц үгээр оролдож алдааны мессежийг шалгасан

&#x20; 3. Нэвтэрсний дараа бараа сагслах үйлдэл

\- Locator-д `getByPlaceholder`, `getByRole`, `\[data-test="..."]` зэрэг орчин үеийн, тогтвортой аргуудыг ашигласан бөгөөд XPath ашиглаагүй — учир нь XPath нь HTML бүтэц өөрчлөгдөхөд амархан эвдэрдэг ба уншихад хэцүү. Харин role/label/data-test дээр суурилсан locator нь дизайны бага зэргийн өөрчлөлтөд тэсвэртэй. (Тэмдэглэл: эхэндээ `getByTestId()` ашиглахаар оролдсон боловч saucedemo сайт Playwright-ийн default хайдаг `data-testid`-г биш, харин `data-test` attribute ашигладаг тул тест timeout болсон. Codegen ашиглан бодит locator-ийг олж, `page.locator('\[data-test="..."]')` болгож засварласан.)

\- Codegen ашиглаж (`npx playwright codegen saucedemo.com`) автоматаар код үүсгүүлж, өөрийн гараар бичсэн кодтой харьцуулсан.

\- Trace viewer ашиглан (`--trace on`) тестийн алхам бүрийг дүрсээр шалгаж, санаатайгаар assertion-оо буруу болгож алдаа хэрхэн харагддагийг ажигласан.



\## Playwright vs Selenium — ажиглалт

Playwright дээр ажиллахдаа хамгийн түрүүнд анзаарсан зүйл бол auto-wait механизм байсан. Selenium дээр элемент хараахан ачаалаагүй үед `sleep()` эсвэл `WebDriverWait` гэх мэтийг гараар бичих шаардлагатай гэдгийг сурсан, харин Playwright дээр `click()`, `fill()` гэх мэт үйлдэл өөрөө элемент бэлэн болтол хүлээдэг тул илүү энгийн, богино код бичих боломжтой байлаа. Driver-ийн тохиргоо мөн их хялбар санагдсан — `npx playwright install` нэг л командаар бүх хэрэгтэй хөтчүүд (Chromium, Firefox, WebKit) татагдаж, тусад нь driver файл татаж PATH-д нэмэх шаардлагагүй байсан нь цаг хугацаа хэмнэсэн.



Codegen хэрэгсэл нь надад locator буруу тохиолдож байхад маш их тус болсон. `getByTestId()` ашиглахад тест ажиллахгүй байсан үед codegen ашиглан вебсайт дээр өөрөө үйлдэл хийж, автоматаар үүссэн кодыг харснаар saucedemo сайт `data-testid` биш `data-test` attribute ашигладгийг олж мэдсэн. Ийм асуудлыг Selenium дээр IDE-ийн тусламжгүйгээр гараар DevTools нээж элемент хайх шаардлагатай байх байсан гэж бодож байна.



Trace viewer бас маш ашигтай хэрэгсэл байлаа. Тест унасны дараа зөвхөн алдааны текст, стек харахаас гадна, тухайн мөчид дэлгэц яг ямар байсныг дүрсээр харах боломжтой байсан нь алдааг олж засахад Selenium-ийн лог болон дан ганц screenshot-оос хамаагүй хурдан, ойлгомжтой байсан. Ерөнхийдөө Playwright нь илүү орчин үеийн, "batteries included" философитой хэрэгсэл гэдгийг мэдэрсэн бол Selenium нь илүү өргөн платформ дэмждэг ч илүү олон зүйлийг гараар тохируулах шаардлагатай хэвээр байна.
